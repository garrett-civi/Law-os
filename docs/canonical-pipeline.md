Canonical Pipeline

Overview

This document defines the canonical end-to-end pipeline of the Law-OS system.

It is the shortest complete representation of how:

world facts → legal recognition → institutional outcomes → enforcement

All other documents expand on this pipeline.

⸻

I. Canonical Stack (Top-Level Architecture)

CAPACITY LEVEL
--------------------------------
what can be done

↓ (exercise)

REALITY / WORLD LEVEL
--------------------------------
events, states, conduct

↓ (recognition bridge)

SYSTEM LEVEL
--------------------------------
legal meaning, evaluation, outcomes

Canonical form:

Capacity Level → exercise → Reality / World Level → recognition → System Level


⸻

II. Unified Legal Pipeline

WORLD
--------------------------------
O → P → R
(observation → perception → record)

ENTRY
--------------------------------
Aₐ  (coercive trigger)
L   (civil / adjudicative recognition)

SYSTEM PROCESS
--------------------------------
W   → authorization
USE → reasoning or execution
USAGE → institutional instantiation

EVALUATION
--------------------------------
Z₁ → coercive legality
Z₂ → verdict audit
Z₃ → outcome audit
ZZ → appellate / meta review

ENFORCEMENT
--------------------------------
Wₑ → USAGEₑ → USE_world

RE-ENTRY
--------------------------------
Aₑ → challenge → Z₁


⸻

III. Dual Output Paths (Invariant)

PATH A — CONSTRUCTIVE
--------------------------------
USE_reasoning → USAGE → artifact → Z audit

PATH B — CONSTRAINT
--------------------------------
USE_reasoning → constraint output

Core rule:

constructive outputs → require USAGE
constraint outputs → do NOT require USAGE


⸻

IV. Path 1 — Coercive Flow

R → Aₐ → W₀ → USAGE₁ → USE_world → Aₑ → Z₁

	•	Aₐ triggers coercive processing
	•	W₀ authorizes force
	•	USAGE₁ creates warrant or authority
	•	USE_world executes coercive action
	•	Aₑ enables challenge
	•	Z₁ evaluates legality

⸻

V. Path 2 — Adjudicative Flow

R → L → W₁ → USE_reasoning
  → USAGE_verdict → Z₂
  → W₂ → USE_reasoning
  → USAGE_remedy → USAGE_judgment → Z₃ → ZZ
  → Wₑ → USAGEₑ → USE_world

	•	L performs recognition (state flip)
	•	W₁ opens reasoning space
	•	USE_reasoning produces candidates
	•	USAGE creates institutional artifacts
	•	Z₂ validates liability
	•	Z₃ validates outcome
	•	ZZ performs appellate review
	•	Wₑ authorizes enforcement
	•	USAGEₑ creates enforcement instruments
	•	USE_world executes judgment

⸻

VI. Recognition and Evaluation Roles

L   = entry (state flip)
Z₁  = coercive-use constraint
Z₂  = verdict audit (requires USAGE_verdict)
Z₃  = outcome audit (requires USAGE_judgment)
ZZ  = mixed review (constraint + downstream constructive effects)


⸻

VII. Core System Invariants

No liability exists in the world layer

All reasoning occurs in USE_reasoning

Not all USE_reasoning leads to USAGE

Constructive outputs create artifacts

Constraint outputs shape validity and permission

Z₂ and Z₃ consume prior instantiated artifacts

ZZ produces mixed outputs (constraint + constructive downstream effects)


⸻

VIII. Final Compression

Facts → Entry → Authorization → Reasoning →

    IF constructive:
        → USAGE → artifact → audit

    IF constraint:
        → validation / limitation

→ enforcement


⸻

One-Line Definition

The system transforms world facts into enforceable outcomes
through structured operators that either build legal artifacts
or constrain what may be built.
