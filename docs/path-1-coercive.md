Path 1 — Coercive Flow

Overview

Path 1 governs the transformation of real-world facts into authorized coercive action, followed by optional post-execution review.

This path controls:

allegation → authority → instantiation → execution → challenge → legality review

It is the only path in the system that permits direct alteration of the world through force or compulsion.

⸻

⸻

II. Stage Breakdown

1. World Observation

O → P → R

	•	O (Observation): raw events and conditions
	•	P (Perception): interpreted awareness
	•	R (Record): persisted facts

Output:

recorded_facts

No legal meaning exists at this stage.

⸻

2. Actionable Allegation (Aₐ)

Aₐ

Trigger into the coercive system.

Requirements:
	•	sworn or attested facts
	•	particularity
	•	credibility
	•	sufficient basis for probable cause

Output:

actionable_allegation

Type:

trigger (no artifact created)


⸻

3. Coercive Authorization (W₀)

W₀

Determines whether force may be used.

Inputs:

actionable_allegation

Outputs:

coercive_authority

Examples:
	•	search warrant authorized
	•	arrest warrant authorized
	•	lawful exception recognized

Type:

constraint (permission granted or denied)

No institutional artifact is created at this stage.

⸻

4. Institutional Instantiation (USAGE₁)

USAGE₁

Transforms authorization into a durable institutional object.

Inputs:

coercive_authority

Outputs:

warrant_record
detention_order_record
coercive_instrument_record

Type:

constructive (artifact created)

This step is required before execution.

⸻

5. World Execution (USE_world)

USE_world

Executes coercive authority in the real world.

Inputs:

warrant_record / coercive_instrument_record

Outputs:

world_altered_state
seized_evidence
custody_change
liberty_restriction

Examples:
	•	search executed
	•	arrest completed
	•	property seized
	•	detention imposed

Type:

world (non-institutional change)

This is the point where force is exercised.

⸻

6. Execution Challenge (Aₑ)

Aₑ

Optional re-entry into the system for review.

Inputs:

execution_facts
record_of_execution

Requirements:
	•	identifiable execution conduct
	•	alleged defect (scope, force, or procedure)
	•	sufficient factual basis

Output:

execution_challenge

Type:

trigger

Important:

Aₑ does not perform review.
It enables review.


⸻

7. Coercive Legitimacy Review (Z₁)

USE_reasoning_coercive_legitimacy → Z₁

Evaluates whether coercive use was lawful.

Inputs:

execution_challenge
execution_facts
coercive_authority_record

Outputs:

lawful_or_unlawful_use
evidence_admissible_or_suppressed

Type:

constraint (no artifact created)

No USAGE step occurs.

⸻

III. Z₁ Test Structure

Z₁ evaluates both structural and conduct-based constraints.

Zb-Dominant (Doctrinal Validity)
	•	warrant or exception validity
	•	scope compliance
	•	procedural regularity
	•	admissibility consequences

Za-Bounded (Execution Conduct Limits)
	•	no excessive force
	•	no abusive execution
	•	no bad-faith expansion beyond authorization

⸻

IV. Output Classification

Aₐ       → trigger
W₀       → constraint
USAGE₁   → constructive
USE_world → world
Aₑ       → trigger
Z₁       → constraint


⸻

V. Core Invariants

Execution occurs before Z₁ review

Z₁ is a direct constraint output (no USAGE)

Aₑ triggers review but is not itself review

Coercive authority must be instantiated before execution

World alteration occurs outside the system layer

Constraint outputs do not create institutional artifacts


⸻

VI. Failure Outcomes

Insufficient allegation → no entry

Authorization denied → no coercive power

Improper execution → suppression / exclusion

Invalid coercive use → downstream evidentiary limits

Severe defects → termination of use or proceeding


⸻

VII. Final Compression

Facts → Allegation → Authorization → Instantiation → Execution

→ IF challenged:
    → Z₁ → constrain legality and admissibility


⸻

One-Line Definition

Path 1 governs how force becomes authorized, executed, and constrained within the legal system.
